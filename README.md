# WalkeDetection3

LiDAR(hokuyohub)のクラスターデータから着地を検出し、足の向きと左右を判定して足跡を描く。

## OSC 受信フォーマット

- ポート: `10001`
- アドレス: `/hokuyohub/cluster`(1メッセージ = 1クラスター)
- 型タグ: `,ihiffffffi`

例:

```
/hokuyohub/cluster 10 1789614771730049000 73625 1.89608 -2.83809 1.83882 -2.94273 2.00459 -2.78891 15
```

| idx | 型 | 例 | 意味 | 取得 |
|---|---|---|---|---|
| 0 | int32 | `10` | クラスター番号。**フレームをまたいだ追跡IDではない**(同じフレーム内では重複しない) | `getArgAsInt32(0)` |
| 1 | int64 | `1789614771730049000` | タイムスタンプ(UNIX時刻 ns) | `getArgAsInt64(1)` |
| 2 | int32 | `73625` | フレーム番号 | `getArgAsInt32(2)` |
| 3, 4 | float | `1.89608`, `-2.83809` | 重心 x, y [m] | `getArgAsFloat` |
| 5, 6 | float | `1.83882`, `-2.94273` | バウンディングボックス min x, y [m] | `getArgAsFloat` |
| 7, 8 | float | `2.00459`, `-2.78891` | バウンディングボックス max x, y [m] | `getArgAsFloat` |
| 9 | int32 | `15` | クラスターの点数 | `getArgAsInt32(9)` |

## 実データ調査(20秒キャプチャ / 1988メッセージ / 602フレーム)

- **フレーム番号とタイムスタンプは完全に1対1**。値が切り替わるタイミングも全メッセージで一致。どちらで区切っても同じ。
- 同じフレームのクラスターは連続して届く(他フレームと混ざらない)。ただし **1フレームが複数パケット・複数 update() にまたがることがある**(602中213フレーム)。
- フレーム番号はループ時以外は常に +1(欠番なし)。
- タイムスタンプ間隔: 平均 33.3 ms(約30Hz)、標準偏差 2.2 ms、範囲 22.8〜40.9 ms。**一定ではない**ので、速度計算はタイムスタンプ差で割ること。
- プレイバックのループ: 約1574フレーム(約52秒)ごとにフレーム番号が 75076 → 73502 のように戻る(タイムスタンプも戻る)。
- 1フレームあたりのクラスター数: 1〜5(3〜4が大半)。
- idx 0 は 5〜17 程度の値で、静止している同じ足でもフレームごとに変わる。追跡は自前でやる必要がある。
- BBサイズ: 幅 中央値 0.18 m(最大 0.57)、高さ 中央値 0.20 m(最大 0.62)。大きいものは足が2つくっついている可能性。
- 座標範囲: x 0.39〜4.95 m、y -5.41〜-0.24 m。
- 点数(idx 9): 5〜77。

### データ2(40秒キャプチャ / 3806メッセージ / 1199フレーム)

- フォーマット・型タグは同じ。フレーム番号とタイムスタンプは1対1。間隔は平均33.3ms(標準偏差1.4ms)。
- ループは約1659フレーム(約55秒)ごと(53904 → 52245)。
- 1フレームのクラスター数は1〜7(3人前後)。BBの中央値は 0.15 × 0.15 m。

## ゴール(仮)

1. 着地の瞬間に **位置・向き・左右** を検出する
2. できればその場の足踏みも検出する(1 が優先)

## 開発方針

堅牢性より **可読性・ロジックの小ささ・調整する変数の少なさ** を優先する。
